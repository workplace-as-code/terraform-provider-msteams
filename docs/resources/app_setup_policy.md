# msteams_app_setup_policy (Resource)

Manages a Teams app setup policy, which controls whether users can pin and upload apps (`CsTeamsAppSetupPolicy`). Attributes left out of the configuration take the Teams default when the policy is created and are not managed afterwards.

## Example Usage

```terraform
# Users cannot upload custom apps or rearrange the app bar.
resource "msteams_app_setup_policy" "locked" {
  name               = "Locked-AppBar"
  description        = "Fixed app bar, no custom app upload"
  allow_user_pinning = false
  allow_side_loading = false
}
```

## Schema

### Required

- `name` (String) The policy name. Changing it creates a new policy. `Global` manages the org-wide default policy: it is adopted instead of created, and destroying the resource only removes it from Terraform state.

### Optional

- `allow_side_loading` (Boolean) Allow users to upload custom apps.
- `allow_user_pinning` (Boolean) Allow users to pin apps to the app bar.
- `description` (String) Description of the policy.

### Read-Only

- `id` (String) The policy name (same as `name`).

## Import

Import using the policy name. The `Tag:` prefix shown by `Get-Cs*Policy` is accepted, and `Global` imports the org-wide default policy:

```terraform
import {
  to = msteams_app_setup_policy.example
  id = "Locked-AppBar"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msteams_app_setup_policy.example
  identity = { id = "Locked-AppBar" }
}
```

Or with the CLI:

```shell
terraform import msteams_app_setup_policy.example "Locked-AppBar"
```

To import every existing object at once, see [Import an existing tenant](https://registry.terraform.io/providers/workplace-as-code/msteams/latest/docs/guides/import_existing).
